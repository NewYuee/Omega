# Omega

个人多设备在线持续办公 Bot，第一阶段原型。Node.js 接入服务持有一个常驻 Codex App Server，响应式 Web 客户端共享其会话、执行与审批状态。

采用 Grok Bot 的客户端/Coordinator 分层思路，但当前 UI 为独立实现，未复制其受原版 renderer 约束的前端。除浏览器外，现提供 Tauri 2 原生客户端工程，面向 macOS、Windows 和 Android。实际构建状态与安装方法见 [原生客户端说明](native/README.md)。

## 启动

需要 Node.js 22.5+（群组状态使用内置 SQLite）、已安装且已登录的 Codex CLI。实际验证版本：Node 26.0.0、Codex CLI 0.153.4。

```sh
cd /Users/newyue/Lab/omega
npm ci
npm start
```

打开 http://127.0.0.1:4310。访问密钥自动生成在 `.omega/access-token`，在本机终端读取并填入页面：

```sh
cat .omega/access-token
```

密钥不会写入 URL，也不会输出到服务日志。浏览器把它保存在当前标签页的 sessionStorage。它代表个人服务访问权，所有持有它的设备都具有相同权限。

登录后点击左下角 **连接设置**，即可修改访问密钥，也可一键随机生成。保存立即生效并持久保留，当前页面自动使用新密钥，其他设备重新登录即可。若部署时显式配置了 `OMEGA_ACCESS_TOKEN`，页面会提示密钥由服务器环境变量管理，不允许覆盖。

默认 workspace 是父目录 `/Users/newyue/Lab`。新建会话可以选择其子目录。工作目录路径属于服务器；只有你主动选择、粘贴或拖入的图片会上传。

## 图片附件与清理

在输入框中粘贴截图（⌘V / Ctrl+V），或点击“＋ 图片”、拖拽图片。上传完成后可预览和移除，支持只发图片或图片加文字。每条最多 4 张，单张最多 8 MB；支持静态 PNG、JPEG、WebP，不支持 SVG、GIF、动画和 HEIC。图片上传失败时请移除后重新选择。

服务端实际解码校验图片，拒绝超过 2400 万像素的输入，纠正方向、去除 EXIF 等元数据，转为最长边不超过 2560px 的 JPEG，并生成最多 320×240 的缩略图。透明区域转为白色；不保留原始上传文件。上传与读取均要求访问密钥，密钥不放入图片 URL。历史正文只携带图片标识，点击才加载缩略图，再点击查看大图；移除附件、关闭大图、切换问答时释放相应浏览器图片引用。

图片及缩略图保存在 `.omega/images/`（设置 `OMEGA_STATE_DIR` 时使用该状态目录的 `images/`）。**从上传时刻起保留 7 天**，不是从最后查看或发送起计算；未发送和发送失败的上传也遵守这个期限。服务启动时检查一次，运行中每小时检查一次；满 7 天立即拒绝读取/再次发送，磁盘文件最迟在下一次检查清除。服务停机期间不执行清理，下次启动补清。

清理仅删除专用图片目录里符合 Omega 命名规则的过期普通文件，不递归删除，不跟随符号链接，不删除文字会话或其他工作文件。文件删除后无法通过 Omega 恢复，历史会显示图片已过期；如需再次使用请重新上传。此策略不负责清除 Codex 或模型服务可能保存的历史、日志、缓存、备份及用户另存的副本。

图片以服务端 `localImage` 输入发送给 Codex App Server，见 [官方图片输入协议](https://learn.chatgpt.com/docs/app-server#turns)。能否识图仍取决于所选模型及其服务配置。

可用环境变量：`PORT`（4310）、`OMEGA_HOST`（127.0.0.1）、`OMEGA_WORKSPACE`、`OMEGA_CODEX_BIN`、`OMEGA_ACCESS_TOKEN`（至少 8 字符）。页面允许手动设置 8–256 字符的密钥，“随机生成”提供 16 位随机十六进制密钥；已有密钥不会自动更换。短密钥更容易被猜测，公网访问应使用 HTTPS，避免弱口令。服务继承已有 Codex 登录与配置；不会复制登录令牌到浏览器。

## 第二台电脑

保持服务器开机并运行 Omega，使用已有 SSH 访问建立隧道：

```sh
ssh -N -L 4310:127.0.0.1:4310 USER@SERVER
```

在第二台电脑打开 http://127.0.0.1:4310 并输入同一访问密钥。两台设备连接同一 App Server，而不是各自启动独立实例。

手机或无需隧道的长期接入，应通过现有私有网络或 HTTPS 反向代理把流量转发到本服务，并关闭 SSE 缓冲。当前没有自动配置域名、证书或 SSH 账户。不要把带访问密钥的 HTTP 流量直接暴露到公共网络。

## 第一阶段能力

### 群组协作 V1

侧栏切换到“群组”后，可以创建项目群组并添加已有会话作为成员，为每个成员填写身份、职责和操作范围。Omega 会为每个群组自动建立一个专用协调者会话；成员仍使用原会话，因此原来的上下文不会被复制或清空。

第一版流程为：多个需求进入队列 → 协调者为每张需求生成带依赖的任务计划 → 用户确认 → 服务端挑选“依赖完成、成员空闲、目录不冲突”的任务并行派发 → 保存成员原始交付 → 协调者审核并形成交付报告 → 用户验收、要求修改或终止。浏览器关闭不会终止服务端调度，多个设备查看同一状态。

群组、成员实际工作目录、需求队列、原始群消息、摘要、任务依赖、唯一派发标识和交付记录保存在 `.omega/omega.sqlite`。每个成员继续在自己会话原有的项目目录工作，因此一个群组可跨多个项目。服务重启时结果不确定的任务会进入“待核对/已暂停”，不会自动重放。相同或父子目录互斥，不同目录可并行；角色描述不代替 Codex 的沙箱和人工审批。

群组可以在 Web 工作台删除。删除前会检查运行任务和待审批；删除后群组需求、任务和协作记录会清理，成员会话及项目文件保持不变，只有该群组专用的协调者会话会一并删除。

已加入的成员可在 Web 工作台继续编辑名称、项目名称、身份、职责、操作范围和擅长任务。成员对应的 Codex 会话与工作目录固定不变；资料调整只用于后续任务派发，不改写历史任务记录。

第一版限制：一个成员会话只能加入一个群组，同一成员一次只执行一个任务；群组默认最多并行 3 个任务，可在 Web 群组工作台调整为 1–10，每张计划最多 8 个任务、2 次返工、12 个调度轮次、单任务等待 45 分钟。目录锁按路径保守处理，尚未区分只读与写入任务。自动提交、推送、部署、删除文件等操作仍受现有审批和用户授权约束。

- 会话列表、新建、历史读取与恢复。
- 会话列表右侧铅笔按钮重命名：1–80 字符，支持保存/取消；名称由 Codex 持久化并实时同步到其他在线窗口，不重载正文或清空输入草稿。
- 垃圾桶按钮删除会话，必须二次确认。调用 Codex 原生删除接口，包含该会话的子会话；不删除项目工作文件。在线窗口同步移除，保留未发送的文字。为避免子会话仍在执行，Omega 有任何任务运行或等待审批时不允许删除；删除期间禁止新建/恢复/提交任务。图片仍按 7 天规则清理，此操作不清除 Omega 去重日志、用量统计或其他服务的备份。
- 手机端顶部菜单打开会话抽屉；默认只显示精简标题栏、历史导航和聊天区域。按钮使用本地 SVG，无外部图标加载依赖；消息表情使用系统 Emoji 字体，最新表情的支持取决于系统版本。
- 输入框从单行自适应增长，最高 120px 后内部滚动；展开按钮进入全屏编辑，收起或按 Escape 保留草稿和图片，成功发送后返回会话。
- 每轮统计：耗时、输入/输出/总 token、缓存命中和思考 token；完成后显示整轮平均输出速度。服务端保存至 `.omega/turn-metrics/`，其他设备及刷新后可读取。
- 输入区的调节按钮打开“模型设置”：从 App Server 的 `model/list` 获取实际目录，只提供对应模型支持的推理档位。保存至 `.omega/model-settings/`，按会话跨设备同步、重启保留；只影响下一轮，不修改进行中的任务。并发修改使用版本检查，过期页面不会静默覆盖另一设备的设置。
- “跟随当前会话配置”表示不传覆盖参数，不是恢复服务器全局默认（Codex 会继承此前轮次的配置）；指定模型后“模型默认”使用该模型目录返回的默认推理等级。每次 `turn/start` 固定提交时的模型/effort 与配置版本，去重重试使用同一次请求；模型不支持图片时会拦截图片发送。说明见 [官方模型目录与轮次接口](https://learn.chatgpt.com/docs/app-server#models)。
- 本轮统计区的“本轮请求”显示 Omega 已记录的提交配置，不代表供应商内部路由后的实际模型；历史中没有记录的配置不推算。模型目录不保证账号额度或供应商可用性，实际拒绝仍显示服务端错误。切换模型不修改审批、安全沙箱或系统全局配置。

统计说明：耗时优先使用 App Server 的 `durationMs` 或开始/结束时间；缺少原生时间时用服务端观察时间并标“约”。整轮平均速度 = 输出 token ÷ 整轮耗时，包含思考、工具和网络等待，不是模型纯生成速率。Token 使用累计计数与本轮开始基线的差值，不累加重复通知或 `last`。缓存命中属于输入细分、思考属于输出细分，不额外叠加。缺少基线、供应商未返回用量或计数重置时显示“暂无”；旧记录只显示已有的真实计时，不回推 token。统计记录不包含消息正文。
- 真实模型流式输出、命令输出和文件变更展示。
- 同一服务的多个窗口共享实时通知和待审批列表。
- 命令/文件审批支持允许本次或拒绝，决议只接受一次。
- 支持 requestUserInput 文本回答；其他请求显示未支持提示，可停止任务。
- 同一线程运行时拒绝另一轮提交；支持中断。
- SSE 自动重连，重连读取服务端历史和审批状态。
- 提交 ID 先落盘，再发送模型请求；服务重启后遇到未知结果不会自动重放。
- 浏览器断开不结束 App Server。服务器停止/重启不保证运行中的推理继续，但已存储历史可恢复。

## 架构

`public/app.js / groups.js → HTTP RPC / SSE → server.mjs → group-orchestrator.mjs → bridge.mjs → codex app-server (stdio)`

Gateway 是所有设备的单一 Codex 连接，统一广播通知和分配审批。Codex 自己管理持久会话，Omega 保存访问密钥、请求去重日志与图片附件；不维护第二份权威聊天记录。助手回复使用 marked 解析 Markdown，经 DOMPurify 白名单清理后显示；用户输入与工具输出保持纯文本。代码块支持复制，外链限定为 HTTP(S)、mailto 或页内锚点。

群组协作是独立的轻量状态层：`groups-store.mjs` 使用 SQLite 保存调度事实，`group-orchestrator.mjs` 负责生成依赖计划、从队列选择可运行任务、并行派发、审核和汇总。SQLite 不复制 Codex 的完整会话历史；详细工具输出仍按需从成员会话读取。

## 验证

```sh
npm test
node smoke.mjs
node browser-smoke.mjs
node images-smoke.mjs
node rename-smoke.mjs
node mobile-ui-smoke.mjs
node delete-smoke.mjs
node model-settings-smoke.mjs
node group-ui-smoke.mjs
```

`smoke.mjs` 需要运行中的服务，会建立一个测试会话并发起一次简短的真实模型请求（可能消耗额度），验证认证、双连接广播、提交去重、持久历史和 resume。

`browser-smoke.mjs` 需要 `npm ci` 和 macOS Google Chrome，创建测试会话并检查登录、新建、两个独立浏览器上下文、页面重载与移动布局；截图保存在 `.omega/`。

`images-smoke.mjs` 在桌面/手机视口验证选择、移除、粘贴、拖拽、纯图/图文发送与按需历史预览。它上传生成的小测试图，模拟模型 RPC，不消耗模型额度；测试图同样在 7 天后清理。`npm test` 覆盖上传权限、格式/大小/像素校验、重启持久化与过期清理，使用独立临时目录。

`mobile-ui-smoke.mjs` 使用模拟数据检查 320/390/1280px 布局、全屏/自适应输入和删除确认/失败。`delete-smoke.mjs` 创建并仅删除自己的空白测试会话，验证真正删除、双窗口同步和刷新；不调用模型。

`model-settings-smoke.mjs` 在新建空白测试会话上验证真实模型目录、档位、保存/取消、双设备同步、刷新和版本冲突；结束后删除该测试会话，不发起推理。`npm test` 使用模拟 App Server 验证实际转发到 `turn/start` 的模型和 effort、执行中改设置、重启持久化及重试不重复提交。

`group-ui-smoke.mjs` 使用模拟群组数据检查桌面与手机工作台、Markdown 交付、计划调整和确认操作，不调用真实模型。`npm test` 还会使用临时 SQLite 和模拟 App Server 跑通创建群组、绑定跨项目成员、需求排队、依赖调度、并行执行、汇总交付和验收。

## 已知边界

- 个人单用户原型；不提供团队角色和租户隔离。
- 未迁移 Grok Bot 插件、reaction、VNC 和本机工具。使用服务端 Codex 已有工具配置。
- 会话列表首批 60 条；浏览器按需保留一轮问答、长正文分段展示。服务端仍使用版本兼容的 includeTurns 读取历史，超长会话首次读取可能较慢。
- 支持图片附件，但通用文件上传和文件浏览器尚未实现。Markdown 中的任意远程图片和内嵌 HTML 交互组件不开放。
- 实时事件不做持久重放；重连以历史快照恢复，短暂工具输出可能仅在最终结果中可见。
- App Server 异常退出后需重启 Omega；服务重启后活动任务不自动重发。
- 请求去重日志持久保存，内存缓存最多 2000 次提交；达到后需在任务结束后重启服务。
- 默认只监听本机。长期无人值守运行、远程域名与手机入口需要部署到你选定的常驻主机。
