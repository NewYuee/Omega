# Omega

**把已有 Codex 会话组织成跨项目协作工作台。**

Omega 是基于 Codex App Server 的自托管、跨设备 AI 工作台。你可以在 Web、Windows/macOS 桌面端和 Android 上继续单个会话，也可以把不同项目的会话加入群组：提出问题、指定负责人、查看执行进度，并在需要时作出决策。成员保留各自的上下文和实际工作目录。

当前版本：**v0.2.0**。面向个人日常使用，不提供多用户权限或租户隔离。客户端共享 React + TypeScript 产品层，服务端统一连接常驻 Codex App Server。

## 能做什么

- **继续已有会话**：分页查看历史与流式回复，重命名、删除、排序，设置模型与推理等级，查看耗时和实际 Token 用量。
- **组织跨项目协作**：已有会话作为成员，按职责自动分配，或用 `@成员` 直接交办；成员进度和答复直接显示在群聊里。
- **按需要协作**：默认直接处理，可为单次提问开启成员交接或只读讨论，设置并发、轮次、时间和 Token 预算。
- **图文混合输入**：单聊和群聊均支持选择、粘贴、拖入图片，图片保留在文字前后的位置；长文本粘贴显示为可整体移除的块。
- **紧凑聊天界面**：可折叠侧栏、自适应输入框、全屏编辑、回复全文复制、空输入框按 ↑ 恢复提问。
- **跨设备接续**：共享执行、审批、未读和群组状态；浏览器关闭不会停止服务端调度。
- **自动化与工具入口**：定时任务、Codex 已配置的 App/MCP/插件连接，以及依赖这些工具的电脑和浏览器操作。
- **日用维护**：服务监督运行、健康检查、备份恢复；异常执行优先核对原轮次，不盲目重复派发。

## 快速开始

服务端需要 Node.js **22.18+**，以及已安装、已登录且可启动 `codex app-server` 的 Codex CLI。客户端设备不需要单独运行 Codex。

```sh
git clone https://github.com/NewYuee/Omega.git
cd Omega
npm ci
npm start
```

浏览器打开 **http://127.0.0.1:4310**。首次访问密钥保存在服务器的 `.omega/access-token`，在另一个终端读取后填入连接设置：

```sh
cat .omega/access-token
```

PowerShell 可使用 `Get-Content .omega/access-token`。密钥不要贴到公开问题、日志或截图中。

默认只监听本机，工作空间默认为仓库的父目录。建议显式设置 `OMEGA_WORKSPACE` 为你的项目根目录；目录均指服务器上的路径。完整环境配置、后台启动、日志和远程连接见 [本地启动与多端编译手册](docs/local-development-and-build.md)。

### 后台运行

```sh
npm run web:build
npm run service:install
npm run service:status
```

系统服务安装支持 macOS LaunchAgent 和 Linux systemd user service。也可运行 `npm run service:start` 使用内置 supervisor，但它仍占用当前终端。服务受监督运行时，控制中心可重启 Omega。

前端改动后运行 `npm run web:build` 并刷新页面；服务端改动需要重启服务。

## 群组：你提问，负责人处理

1. 创建群组，添加已有会话，为成员设置名称、职责和实际工作目录。
2. 直接提出问题，让协调者选择负责人；或写 `@成员` 绕过协调者分配，直接交给该成员。引用追问会继续交给原回答成员。
3. 多个问题可以同时排队。调度器挑选依赖满足、成员空闲、目录读写不冲突的任务执行。
4. 群聊显示进度、答复与必要的决策表单；问题定位栏用于查看状态和跳转，不要求逐条手动验收。有问题继续追问即可。

| 执行模式 | 用途 |
| --- | --- |
| 直接处理（默认） | 负责人完成当前问题，不自动增加协作轮次 |
| 允许交接 | 必要时将后续工作交给其他成员，默认最多 10 轮 |
| 讨论（只读） | 多个成员分轮补充意见，默认最多 3 轮；未指定成员时全员参与 |

模式和协作预算在输入框底部图标菜单中设置。交接与讨论可设置 **1–100 轮**；群组并发默认 3，可设置 **1–10**。同一成员仍串行，不同项目可并行，只读任务使用读访问冲突规则。职责文字不替代实际目录配置，也不构成权限隔离。

预算控制的是**下一步是否继续派发**，不会到限强杀当前任务，不是严格费用封顶。时间包含排队和等待；Token 依赖实际观测数据，目前只累计成员执行，不包含协调者。

成员沿用原有 Codex 上下文；群组按需补充当前话题增量和必要依赖结果，不把全部群聊反复灌入每个成员。较长消息提供片段及完整原文文件入口；提供入口不等于模型已经读取。

成员资料可以编辑。更换关联会话或目录前，需要处理或取消仍在执行、待核对、待决策的任务。一个成员会话目前只能加入一个群组。删除群组不删除成员会话或项目文件，但会删除群组记录及其专用协调者会话。

更多说明：[协作模式](docs/group-collaboration-modes.md) · [预算、目录、恢复与轻量交接](docs/group-daily-use.md)

## 输入、附件与历史

- **Enter 发送，Shift+Enter 换行**；输入框随内容增长，超过高度后滚动，也可全屏编辑。
- 空输入框按 **↑** 恢复本次打开页面后，该会话上一次成功发送的提问；不同会话分别记录，刷新后不保留。长文本块可以恢复，图片需要重新添加。
- 回复的“**复制全部**”复制完整 Markdown 原文，单聊长回复会按需读取全部分页，而不是只复制当前可见段落。
- 长文本粘贴保存为服务端文本附件，输入中显示可预览、可整体删除的块；这不是任意类型文件上传。
- 会话支持按最近更新、创建时间、名称或自定义顺序排列。排序偏好保存在当前浏览器/客户端，不跨设备同步。
- 单聊历史按轮次和条目分页；群聊窗口最多 120 条，视口外 Markdown 卸载，历史替换窗口而不是无限追加。

### 图片

单聊和群聊均支持静态 PNG、JPEG、WebP，每条最多 **4 张**，单张最多 **8 MB**；不支持 SVG、GIF、动画和 HEIC。上传失败时移除后重试。群组图片会随问题传给协调者和执行成员，识图能力取决于所选模型及服务配置。

服务端校验和重新编码图片：最多 2400 万像素，纠正方向、去除元数据、最长边缩至 2560px，保存为 JPEG 并生成缩略图；透明背景转为白色，不保留原始上传文件。图片读取需要访问密钥，历史按需加载。

图片从**上传时刻起保留 7 天**，未发送的图片也适用。到期立即拒绝读取和再次发送；启动时和运行中每小时清理一次过期文件。清理不影响文本会话与项目文件，也不负责清除 Codex、模型供应商、备份或另存的副本。图片说明位于图片按钮悬停提示中。

## 多端客户端

各端连接同一个 Omega 服务端，不在客户端复制一套 Codex 执行环境。

| 平台 | 实现 | 常用命令 |
| --- | --- | --- |
| Web | React + TypeScript | `npm start` |
| Windows / macOS | Electron | `npm run desktop:dev` / `npm run desktop:package` |
| Android | Tauri 移动容器 | `npm run mobile:android:build:local-release` |

桌面安装包输出到 `release/`，提供托盘、菜单和任务完成通知。Android 首次构建需准备 Rust、JDK、SDK/NDK 并执行 `npm run mobile:android:init`；本地 release 命令构建非 debug APK，再以本地密钥签名，**不是无签名 APK**。正式分发应使用自己的签名配置。

构建前置条件和平台边界见 [多端编译手册](docs/local-development-and-build.md)、[Android 说明](native/README.md)。当前没有已验证的 iOS 发布流程；Tauri 不再承担桌面外壳。

## 控制中心与连接

- `⌘/Ctrl + K`：搜索命令、会话和已建立索引的正文。
- `⌘/Ctrl + Shift + K`：打开控制中心，管理定时任务、连接与插件、电脑/浏览器操作及系统备份。
- 自动化绑定已有会话，支持间隔或指定时区每日执行；成员忙碌时不会插入并发轮次。
- 插件连接使用 Codex App Server 的相关接口，部分仍属实验协议。
- 电脑和浏览器操作依赖会话已配置且获准的工具，不自带通用远程桌面驱动，也不绕过审批。

单聊搜索索引在查看历史或收到消息时增量建立，尚未访问的旧正文不保证能搜到。多设备共享未读状态和待审批，断线后使用事件缓冲或历史快照校准，不自动重发消息。

## 数据与安全边界

Omega 是**个人单用户服务**。所有持有访问密钥的设备拥有相同服务权限，不应把密钥分享给不可信用户。浏览器密钥存放在当前标签页 sessionStorage；原生客户端使用系统安全存储，实际可用性受平台及签名配置影响。

默认数据目录为 `.omega/`，可用 `OMEGA_STATE_DIR` 修改：

| 数据 | 保存位置 |
| --- | --- |
| 群组、成员、问题和调度事实 | `omega.sqlite` |
| 图片及缩略图 | `images/` |
| 话题/依赖原文的派生文件 | `group-handoffs/`，目前不自动过期 |
| 定时任务 | `automations.sqlite` |
| 模型设置 / 轮次统计 | `model-settings/` / `turn-metrics/` |

Codex 管理成员会话的持久上下文，项目文件仍在各自工作目录；Omega 不维护第二份完整的权威 Codex 历史。备份恢复只作用于 Omega 管理的数据，排除访问密钥，不恢复项目文件或 Codex 自己的会话历史。

常用环境变量：`PORT`（4310）、`OMEGA_HOST`（127.0.0.1）、`OMEGA_WORKSPACE`、`OMEGA_STATE_DIR`、`OMEGA_CODEX_BIN`、`OMEGA_ACCESS_TOKEN`。页面可修改 8–256 字符密钥；显式设置环境变量密钥时不能在页面覆盖。

远程访问使用 SSH 隧道、私有网络或 **HTTPS** 反向代理，并关闭 SSE 缓冲。HTTP 兼容不提供加密，不要把明文密钥流量暴露到公网。提交、推送、部署、删除等操作仍遵守用户授权和 Codex 审批。

重启或网络中断后，未知执行不会盲目重放。群组优先核对持久化的原轮次，再回收结果或提示人工处理；停止执行不回滚已经产生的文件修改。

## 架构与验证

```text
Web / Electron / Android
        ↓ HTTP + SSE
Omega TypeScript 服务
        ↓ 群组调度 / 自动化 / 审批与执行状态
Codex App Server
        ↓
成员会话上下文、工具与各自项目目录
```

共享前端使用 React，Markdown 经过 DOMPurify 清理。服务端以 Node 原生 TypeScript 类型擦除运行，SQLite 保存群组调度事实；根目录部分 `.mjs` 仅作转发。客户端借鉴 Grok Bot 的分层思路，UI 为独立实现。

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:browser
npm run test:performance
```

浏览器回归覆盖手机/桌面布局、群组历史、输入、图文顺序及复制等交互，使用模拟接口，不消耗模型额度。真实服务 smoke 脚本可能创建会话并调用模型，运行前请查阅脚本说明。

CI 仅允许仓库所有者触发执行：推送 `main` 或手动运行只做源码验证；推送新建的 `v*` 版本标签（例如 `v0.2.1`）时，验证通过后才构建 Android、Windows 和 macOS 安装包。仅在本地创建标签不会触发构建，更新已有标签或手动选择标签运行也不会打包。详见 [构建工作流](.github/workflows/build.yml)。
