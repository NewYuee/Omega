# 群组协作模式

每次发送前，点击群组输入框底部的执行模式图标，选择本次提问的模式；轮次在旁边的协作预算图标菜单中设置。发送成功后恢复“直接处理”，避免后续普通问题意外进入协作。

- **直接处理**：默认模式。`@成员` 直接派发，引用追问继续交给原成员；没有指定成员时由协调者选负责人。
- **允许交接**：当前成员完成工作后，可以提出结构化交接请求，指向群内其他成员。后续任务沿用接收成员自己的目录和上下文，并接收前置结果。普通回复中的 `@` 不会触发交接。
- **讨论（只读）**：指定多个成员参与，未指定时由全体成员参与。每轮参与者可以并行回复；所有人完成后才进入下一轮，补充不同意见和新事实。全员无补充时提前结束。讨论不执行代码修改或发布。

交接默认 10 轮，讨论默认 3 轮；两种模式都允许输入 1–100 的整数。首轮也计入上限，交接按任务链的深度计轮次。到限时保留后续排队任务，调整总预算后可以继续，不重复执行已完成的任务。单问题保留 3000 个任务的防失控上限。原有并发数和目录冲突控制继续生效。时间、Token 预算和详细边界见 [日用说明](group-daily-use.md)。

聊天中显示成员处理轮次，交接对象与目标直接记入消息。进度详情默认折叠，正式答复与决策表单直接展示。原提问旁和正在处理提示中的“停止协作”会取消尚未完成的工作，并尝试中断当前执行；已发生的文件修改不会自动回滚。

成员交接协议（仅允许交接模式生效）：

```text
<omega-handoff>{"tasks":[{"memberId":"群内成员 ID","objective":"必要的后续工作"}]}</omega-handoff>
```

单次最多交接 3 人，不能指向自己、重复对象或群外成员。交接创建与当前结果保存处于同一数据库事务，服务恢复采用相同完成入口，防止重复接续。讨论无补充使用 `(pass)`，不在聊天中新增空洞答复。

如需用户决定，现有决策表单优先处理；用户提交选择后，该成员继续执行，再决定是否交接。

## 讨论如何收敛

每轮成员发言结束后，协调者以只读主持人身份整理共同方向、分歧、推荐方案及下一步。小结直接显示在群组消息中；下一轮先等待小结，再围绕其中的未解决问题回应具体成员的观点，避免各自重复回答原问题。成员的职责与技能会作为分析视角，但不决定谁的意见优先。

- 没有必要继续，或全员 `pass`：发布讨论结论，不再消耗剩余成员轮次。`pass` 只表示没有补充，不代表赞成。
- 达到预算：发布阶段小结并保持暂停；追加预算才能继续，不自动转成执行任务。
- 小结失败：暂停并显示错误，明确重试后才再次生成。派发结果未知时只尝试接回原执行，不能确认原执行时不自动重发。
- 每个完成轮次额外使用一次协调者模型调用，不占成员轮次额度；这是收敛与预算暂停说明的额外成本。不会无限自动重试。

讨论结论是建议，不是已实施的结果或实施授权。此流程用于后续讨论；不会自动重新调用模型补写已经结束的历史讨论。

### 主持人的归因与收尾

成员观点逐条附发言者和原文引文，服务端核对任务来源与引文是否真实存在；不使用“全员一致”等集合归因。用户要求、主持人建议与成员明确表达的意见不能混为一谈，未表态和 `pass` 不补算支持。引文存在不等于已验证技术事实，语义是否充分支持观点仍需要模型判断。

未解决项分成三类：可继续比较的方案分歧、需要查证或实测的事实、确需用户决定的事项。存在第一类且有可接续任务时继续讨论；仅剩后两类时可以停止辩论，但明确保留未完成项。主持人须按本次目标说明收尾理由：可行性咨询不强求实现细节全部定案，方案定案也不能仅凭总体可行提前结束。预算暂停或成员无新增导致的停止不代表分歧已经解决。下一步统一标注为“建议，尚未派发或执行”。

无法通过引文或结构校验的小结会暂停等待处理，不发布未经校验的归因。升级前已保存的历史小结不重写；若升级时尚有旧格式小结在途，校验失败后需明确重试生成新格式，不自动重复派发。
