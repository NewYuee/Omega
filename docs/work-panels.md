# 待处理、仓库变更与自动化运行历史

这三项是在现有会话、审批和调度之上增加的查看与处理入口，不引入人工验收流程，也不增加 Git 写操作。

## 全局待处理

主界面标题栏的「待处理」显示当前数量，单聊、群聊和移动端都可打开。

- 聚合 Codex 执行审批 / 补充信息、群组待决策、异常与预算暂停，以及自动化失败 / 结果待核对。
- 群组决策复用原方案表单；审批复用原审批卡片。
- 原执行待核对走已有恢复流程，不直接重新派发。
- 失败任务重试保留确认；重试不会回滚文件修改。
- 决策 ID、审批请求 ID、群组更新时间及运行 ID 用于拦截已过期操作。
- 标题数量每 10 秒更新，打开的列表每 5 秒更新；不是瞬时推送。页面隐藏时暂停轮询。
- 每页 30 项。计数直接查询状态，不加载全部聊天历史。正常完成不进入待处理计数。

## 只读仓库变更

标题栏「变更」→ 选择会话 → 选择未暂存 / 已暂存范围。

- 工作目录由服务端读取所选会话的真实信息，客户端不能提交任意目录。
- 仓库根目录必须在该会话工作目录范围内；从仓库子目录启动的会话需要切换到仓库根目录会话查看。
- 显示仓库路径、分支及改动文件；每页最多 50 个文件，点击后读取 diff。
- 未跟踪文件只展示文件名，不直接读取正文。二进制差异由 Git 提示，不渲染二进制内容。
- Git 列表输出上限 2 MiB，单文件 diff 上限 512 KiB，每个 Git 子进程超时 10 秒；超限显示错误，不无限加载。
- 禁用外部 diff、textconv、clean/process 过滤器和 fsmonitor，使用字面文件路径参数。
- 可选中 diff 片段引用给对应会话，追加到输入草稿，不自动发送。

**展示的是仓库当前变化，不是“本次任务独占的修改”。** 其他会话和人工修改也可能在其中；读取过程中仓库变化时，请刷新核对。

本版没有暂存、提交、推送、回滚、自动合并、worktree 管理或可执行 HTML 预览。

## 自动化运行历史

工作控制中心 →「运行历史」→ 选择自动化。

- 每次运行拥有独立 ID，记录计划、开始、结束时间、会话、实际轮次、状态及错误。
- 会话忙碌时记录一条等待记录，不反复创建新记录；空闲后由调度器继续。
- 排队可取消，跳过本次计划；关闭自动化也会取消尚未开始的排队。
- 已开始的执行仍在原会话停止。取消不回滚已有文件修改。
- 服务重启或无法确认是否已提交时标记「结果待核对」，不会自动重放。
- 「核对原轮次」只读取原轮次结果，查不到或仍在运行时继续保持待核对。首版最多检查最近 100 轮；无法定位时请打开原会话核查，不提供强制重发按钮。
- 每页 30 条运行记录；可直接打开关联会话和轮次。历史从本次升级开始记录，旧版本只保留最新状态，不补造历史。
- 状态与运行记录在同一个 SQLite 事务内更新；无需额外调用模型生成摘要。

## 更新与验证

执行 `npm run web:build` 后，需要重启 Omega 服务端以加载新接口和数据库迁移，再刷新页面。不要在执行任务或等待审批时强行重启。

测试包含数据库状态迁移、排队与早到完成事件、Git 路径和过滤器边界、390px / 1280px 面板交互。
