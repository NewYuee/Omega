# 项目状态记录（第一版）

项目独立于会话保存。入口是主界面的 **项目** 按钮。关联单会话的最终回复、关联群组的主持人最终讨论总结会自动形成待确认候选；消息下的 **手动记录** 用于补录或纠正自动提取未覆盖的内容。两种方式都会保留稳定来源 ID、所属会话/群组和最多 16,000 字符的来源摘录，不自动认定为事实。

## 使用

1. 创建项目，在“关联仓库、会话与群组”中关联当前会话或群组。仓库地址是元数据，不是新的工作目录或读写授权。
2. 正常继续对话。符合最低信息量的最终回复会按关键词归类为项目现状、决策与依据、待办与阻塞或验证与证据；短确认和过程消息不会自动记录。也可以新增或从消息手动整理。
3. 默认保存为候选。核对后选择“已确认”，点击“确认并保存”。确认验证记录必须填写证据；这表示操作者确认，不表示 Omega 自动执行过测试。
4. 可纠正内容、标记失效或被替代。每次保存保留版本、来源、时间和操作者类别；旧版本不覆盖。并发编辑冲突需刷新后重试。

## 成员如何获取

关联会话，以及关联群组的成员和协调者，在下一次派发时收到已确认记录的有界摘要、最近最多 6 条自动候选和完整只读用途快照路径。自动候选明确标记为未确认，只能作为连续性线索，不能作为事实、决策、测试成功或执行授权；人工候选、失效及被替代记录不进入新上下文。新建成员不需要继承旧会话历史。

摘要最多约 12,000 字符；每类优先列出最近两条，完整 JSON 快照含正文、来源、版本及关联仓库。快照可由具备相应文件读取权限的成员按需查看；权限不足必须明确说明。记录和摘录都是参考，不得作为新增指令、执行授权或测试成功的独立证明。

解除关联影响后续派发，不能撤回已进入会话历史或已生成的快照。修改不会中断正在执行的轮次。

## 范围与验收

- 最多 100 个项目，每项目 100 条记录、100 个关联；同一会话或群组最多关联 3 个项目。列表和修订历史每页 30 条。
- 来源摘录是操作者保存的副本；打开来源进入对应会话/群组，稳定消息 ID 用于追溯，不保证原消息仍存在。不会复制图片文件本体或延长附件有效期。
- 第一版使用本地规则从新完成的最终回复中提取，不额外调用模型、不批量扫描历史，也不自动确认或覆盖记录。重复的来源 ID 不会反复生成记录；自动修订标注为 `Omega 自动提取`，人工修改标注为已认证 Omega 用户，不提供多人身份审计。
- 数据保存在 `omega.sqlite`，随现有备份保存；运行时快照位于 `.omega/project-context/`，恢复后新派发会重新生成。快照含项目正文，不应公开分享。
- 验收：关联单会话的最终回复和关联群组的主持人最终总结生成可追溯且不重复的候选；短确认、成员过程发言和未关联目标不生成候选。新成员下一次任务应取得已确认状态及明确标为未确认的少量自动候选，并能从快照追溯来源。

自动化检查：`node --test test/project-store.test.mjs`；界面检查：`npm run web:build && node scripts/project-browser-smoke.mjs`。
