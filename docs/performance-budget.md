# Omega v0.2 性能预算

Omega 的性能目标不是一次加载全部历史后依赖设备硬扛，而是让浏览器只持有用户当前正在阅读的窗口。以下预算作为 v0.2 的回归门槛。

| 场景 | v0.2 预算 | 约束方式 |
| --- | ---: | --- |
| 单聊轮次目录 | 每页 60 轮 | 服务端 `thread/turns/list` 分页 |
| 单聊兼容窗口 | 每页 10 轮 | `thread/items/list` 不受支持时使用 `itemsView: full` |
| 单聊正文 | 同时完整展示 1 轮 | 切换轮次时释放上一轮条目 |
| 单个长条目正文 | 12,000 字符一页 | 工具输出和长正文延迟读取 |
| 群聊消息窗口 | 最多 120 条 | 向前翻页时替换当前窗口 |
| 群组需求摘要 | 最近 50 条 | 详细消息通过问题定位读取 |
| SSE 短时补发 | 最多 512 个事件 | 超出后回到快照与分页历史 |
| 群聊压力回归 DOM | 少于 2,000 节点 | `npm run test:performance` |
| 60 次历史窗口切换 | JS heap 净增长少于 16 MiB | 强制 GC 后测量 |
| 压力窗口重绘 | 平均低于 50 ms/次 | 真实 Chromium + React 构建 |

性能回归测试需要本机 Omega 正在运行，并能通过 `http://127.0.0.1:4310` 加载当前 `web-dist/`。它会拦截 API、使用模拟长消息，不调用 Codex、不消耗模型额度，也不写入真实会话：

```sh
npm run web:build
npm run test:performance
```

预算用于发现明显退化，不等于所有手机都能达到相同帧率。Android 真机仍需用长会话验证输入、滚动、切换历史和后台恢复。如果某次产品需求确实需要提高窗口上限，应同时更新预算、压力样本和实机验收记录，不能只放宽断言。
