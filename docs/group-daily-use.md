# Omega 群组日用：预算、项目目录与轻量交接

## 使用方式

- 成员管理顶部显示协调者。点击“指定会话”可改绑到已有会话；不能与本群成员或其他群组共用，且目标会话须已有可恢复的首轮记录。改绑保留旧历史，删除群组时也会保留你指定的会话。
- 普通会话列表会合并显示已绑定的成员和协调者，并标注“群组成员”或“协调者”。尚未产生首轮记录的空会话也会显示；首次打开时只在确认没有执行轮次或待核对派发后安全重建绑定。
- 默认仍是直接处理。不写 @ 时按职责选择成员；写 @ 时直接交给指定成员。
- 输入框底部的协作预算图标可设置本问题总分钟数和已观测 Token 数，0 表示不限；交接或讨论模式下还可设置轮次。
- 问题定位 → 分配与执行详情 → 调整预算 / 继续，可以调整总轮次、总时间和 Token 上限。
- 达到轮次上限时，后续交接任务保留为排队状态，不会把未执行的工作当成已完成。
- 追加的是总预算，不是增量。例如已经消耗 10000 Token，要再提供 10000，应将总预算设为 20000。

## 恢复与暂停

问题列表默认展示最近 50 项，但按问题 ID 执行和恢复不受这个窗口限制；显式选择的旧问题会附带到当前视图，总数按数据库实际记录统计。

恢复先分页查找原执行轮次，再判断等待期限。超过原期限但已完成的结果仍可正常回收；仍在运行或分页异常时保留待核对状态，不自动重发。分页游标重复和超过安全扫描上限不会被误判成“轮次不存在”。

新建的协调者或成员会话若在首次执行前随服务重启而丢失，且没有原轮次或派发记录，Omega 会在下一次派发时创建替代会话。旧版本将这种成员任务误标为“结果待核对”时，只有确认提交账本中没有该派发，点击“重试失败任务”才会重新排队；其他结果不明的任务仍不自动重发。

暂停原因持久化为 `budget`、`recovery`、`execution`，分别对应追加预算、核对原执行、重试失败任务。恢复结果或提交用户决定不会解除预算暂停；调整预算也不会直接解除尚未处理的执行异常。

## 预算执行边界

预算是后续派发的闸门，不是实时强杀或严格费用封顶：已经启动的任务继续完成，结果仍会保存。

时间从首次成员任务派发开始计算，包含排队、停机和等待用户决定的时间。单任务原有超时保护继续生效。

Token 仅累计成员执行轮次中实际观测到的用量，同一轮的重复快照不会重复计费；协调者用量暂未纳入。服务端没有提供可用用量或基线丢失时显示未知，不以字数估算。因此不能当作严格费用控制。

只读讨论中，所有成员都 `(pass)` 或重复上一轮答案时结束讨论。交接中，同一成员、同一目标、同一结果重复至少三次时，暂停后续派发；用户调整预算后可继续。它是确定性的重复检测，不是对语义进展的可靠判断。

总轮次仍限制在 1–100。超过 100 轮需要另开问题；单问题还有 3000 个任务的防失控上限。

## 职责与目录

- 职责范围、身份、项目名称：帮助自动选择负责人；项目名称也作为并发隔离标识，同一父目录下不同项目可并行写入，同名项目仍按重叠目录互斥。
- 实际工作目录：用于成员执行请求和读写冲突判断，必须在关联会话目录内。
- `/work/project-a` 和 `/work/project-b` 可以并行；涉及 `/work` 的写任务会与子目录冲突。
- 同一个成员会话仍串行；只读任务沿用现有读访问规则。

目录冲突判断是调度规则，不代表文件系统权限隔离。成员仍须遵守操作限制。

## 轻量交接

话题增量每次仍处理最多 24 条候选消息、约 10000 字符正文。单条超长消息不再只截断后跳过，而是提供首尾片段及完整原文文件；多条消息超出本次正文预算时，未包含的消息留待下次。

只有原文文件准备完成、执行接口返回轮次 ID 后，才确认本次增量已提供。文件失败或启动结果未知不会推进游标。这个记录表示“内容或原文入口已提供”，不等于模型已经读取文件；提示会要求模型在需要具体细节时先读取原文。此前旧版本已经推进的游标不会自动回放。

派发使用当前问题、必要依赖结果和本话题未交付的信息，不重复发送成员身份和全部职责。

依赖结果在提示中展示有长度限制的片段，附带任务、原轮次和完整文件位置。完整结果保存在 SQLite；派发时按需生成私有、不覆盖的交接文件：

`OMEGA_STATE_DIR/group-handoffs/<内容哈希>.txt`

默认位置为项目的 `.omega/group-handoffs/`，文件权限为 0600（支持 POSIX 权限的平台）。这些派生文件当前没有自动过期策略；不会纳入源代码。更换电脑客户端不影响服务端保存的记录。

## 页面性能

- 消息窗口保持最多 120 条；加载历史替换当前窗口，不无限追加。
- 只渲染视口附近的 Markdown，远处内容卸载，保留高度占位。
- 折叠的处理进度不提前渲染 Markdown。
- 房间状态响应不携带任务结果、目标全文和完整计划的重复副本。
- 每个问题的状态视图最多保留 120 个非终态任务和最近 80 个终态任务，优先显示待决策、运行中与异常项；完整聊天仍可翻阅。
- 迟到的历史请求和旧群组刷新不能覆盖当前视图。

## 验证

```bash
npm run typecheck
npm test
npm run test:browser
```

浏览器回归使用模拟接口，不启动真实模型任务，覆盖 390px/1280px、历史窗口、Markdown 按需渲染、进度折叠、回车/换行、全屏编辑、侧栏和取消。优先使用 `OMEGA_TEST_CHROME` 指定的浏览器，其次使用本机 macOS Chrome，否则使用 Playwright Chromium：

```bash
npx playwright install chromium
```

CI 在原有所有者限制下安装 Chromium 并运行浏览器回归。连接/恢复、重复派发与协作协议仍由服务端自动化测试覆盖；不声称完成了所有真实 FRP 网络环境的端到端验证。
