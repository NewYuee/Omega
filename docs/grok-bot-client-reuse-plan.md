# Omega 客户端升级计划：复用 Grok Bot，接入 Codex App Server

日期：2026-09-11
状态：方案阶段，尚未开始客户端迁移

## 1. 目标

以本地 `grok-bot-0.18-reconstructed` 仓库中可维护的客户端源码和交互为基础，升级 Omega 的聊天与群组体验，通过 Omega 服务端接入 Codex App Server，实现个人多设备持续办公。

用户在 Web、Windows、macOS、Android 上访问同一服务端，继续使用已有会话上下文和项目工作目录；客户端断开不影响服务端执行，重新连接后可以查看处理进度和结果。

本计划只约定后续实施方案，不代表相关迁移已经完成。本文档的编写不涉及修改运行中的业务代码或重启服务。

## 2. 现状与判断依据

### 2.1 Omega

- 已有 Web 前端和 Tauri 原生客户端工程。
- 服务端已有认证、事件推送、历史分页、图片管理、会话操作、模型设置及群组调度能力。
- 群组成员关联已有会话，成员按各自工作目录执行任务。
- 群聊支持连续提问、成员回复和进度展示、指定成员及并发调度。
- 当前前端以原生 JavaScript 和 CSS 为主，许多基础交互仍在逐项补齐。

### 2.2 Grok Bot 重建仓库

本地仓库：`../grok-bot-0.18-reconstructed`。

已检查的源码入口包括：

- `frontend/src/production/ProductionRenderer.tsx`：组合聊天、输入框、侧栏、草稿、成员设置等模块。
- `frontend/src/production/coordinator-client.ts`：客户端对协调服务的调用与事件订阅。
- `frontend/src/recovered/features/conversation/workspace/`：聊天界面和状态管理。
- `frontend/src/recovered/features/conversation/tool-results/`：工具执行结果展示与协议转换。
- `source/electron-main/`、`source/electron-preload/`：Electron 桌面运行时与桥接。

该仓库是非官方重建工程，不能视作完整原始源码。根 README、前端 README 对默认打包界面的描述存在差异；打包脚本仍有保留原版编译界面的路径。迁移前必须逐个确认组件是否由可读源码构建、实际依赖哪些接口，以及是否存在未完成或仅演示的行为。

仓库现有 Codex 路由使用直接 Responses 传输，并非 Codex App Server 接入。仅切换它的模型提供方不能复用 Omega 中的 Codex 会话和群组调度。

## 3. 总体方案

保留 Omega 服务端与 Tauri 外壳，建立新版 React/TypeScript 客户端，按功能迁移 Grok Bot 中可复用的组件和交互，通过适配层调用 Omega 服务端。

```text
Web / Windows / macOS / Android
              │
              ▼
Omega 新版客户端
（复用 Grok Bot 组件和交互）
              │
              ▼
客户端接口与平台适配层
              │
              ▼
Omega 服务端
（认证、事件同步、历史分页、图片、群组调度）
              │
              ▼
Codex App Server
（已有会话、上下文、工具执行与审批）
```

客户端不自行启动另一套 Grok Bot 代理执行流程。模型调用、任务执行、审批和会话状态由服务端链路统一管理。桌面本地路径与服务器项目路径必须明确区分：选择附件可以访问本机文件，项目执行仍使用会话在服务器上的工作目录。

## 4. 复用范围

| 能力 | 实施方式 | 主要适配点 |
| --- | --- | --- |
| 会话列表、搜索、折叠和宽度拖动 | 优先迁移可读组件及状态管理 | Omega 会话标识、分页和列表接口 |
| 输入框、草稿、附件、引用回复 | 迁移组件与交互 | 上传接口、回复定位、发送状态 |
| Markdown、代码和执行结果卡片 | 复用展示组件 | Codex 消息及工具事件转换 |
| 历史分页、消息定位、流式更新 | 复用交互和适用的数据结构 | Omega 历史协议、增量事件和缓存 |
| 头像、成员设置、群组侧栏 | 复用组件并接入现有群组功能 | 成员身份、职责、会话和目录关联 |
| 快捷键、菜单、弹窗 | 按场景迁移 | 浏览器、桌面、手机的输入差异 |
| 通知、托盘、窗口操作 | 按需通过 Tauri 实现 | Electron 桥接替换、平台能力检测 |
| 云电脑、插件执行、自动化 | 暂不纳入首版 | 需要独立后端支持和完整能力评估 |

复用以可读、可构建、可维护为准；缺少源码的行为可依据现有客户端交互重新实现。迁移时记录来源、保留适用声明，并核对所用代码和资源的许可条件。首版不把原版压缩产物作为 Omega 的长期业务源码。

## 5. 适配层设计

### 5.1 业务接口

让组件依赖 Omega 自己的客户端接口，避免将 Grok Bot 的协调器协议扩散到整个前端。拟分为：

- 会话：列表、创建、重命名、删除、历史读取、消息定位。
- 对话：发送、停止、模型与推理等级设置、审批响应。
- 事件：连接状态、消息增量、工具进度、执行完成、错误、用量。
- 附件：上传、预览、读取、过期状态。
- 群组：成员管理、提问、指定成员、回复关联、并发设置、问题进度。
- 平台：文件选择、剪贴板、外链、通知、窗口控制和凭据保存。

上述为逻辑边界，不要求每项新建 HTTP 接口。优先复用现有接口，缺失能力再补充服务端契约。

### 5.2 消息与执行状态

统一映射会话、轮次、消息、工具执行和群组问题的标识，保留原始服务端 ID，保证历史定位和引用可靠。

展示模型至少区分用户消息、助手回复、公开进度、工具调用、审批、错误及结束状态。不要把所有事件都拼成纯文本，也不要把思考摘要、工具输出和最终答复混在一起。

流式增量按消息 ID 合并；完成事件校准最终内容；重连通过服务端状态和历史补齐。失败或中断不能显示成已完成。仅展示服务端实际提供的内容与统计，不推测缺失的 token 数或执行时长。

### 5.3 发送与恢复

发送要区分“正在提交”“服务端已接收”“等待成员”“正在执行”“已回复”“失败/中断”。提交成功后允许继续输入新问题。

网络超时不等于服务端未接收。若当前契约不足以判断提交结果，需要补充请求标识、去重或状态查询后，再启用自动重试，避免重复执行。

### 5.4 数据归属与多端同步

- 服务端保存会话、群组、执行状态、图片和项目数据。
- 客户端保存本设备布局偏好、有限缓存与草稿；首版草稿不承诺跨设备同步。
- 多端操作以服务端返回结果为准；审批、停止和成员编辑需处理并发变化。
- 继续遵守服务端图片超过 7 天清理的规则，过期附件显示清楚的占位提示。

## 6. 首版体验要求

### 单会话

- 明确区分用户消息和成员回复，支持流式答复、执行进度和历史定位。
- 桌面侧栏可折叠并记住选择；手机采用抽屉，保留足够聊天空间。
- 输入框随内容增高但有上限，支持全屏编辑并保留草稿及引用。
- Enter 发送、Shift+Enter 换行；中文输入法组合输入期间不误发送。
- 支持图片粘贴和上传、模型设置、停止执行及审批。

### 群组

- 以聊天室为主界面，成员直接展示进度和回答。
- 明确 `@成员` 时按现有直接路由规则处理；未指定成员时由现有调度器分配。
- 可以持续提问，忙碌成员的任务进入等待，不阻塞其他可执行问题。
- 保留成员工作目录、依赖、并发及目录冲突规则。
- 右侧作为问题定位栏，展示是否回复、处理状态和可获得的时长。
- 无需逐条手动验收，用户通过追问继续推进工作。

## 7. 分阶段实施

### 阶段一：确认可复用模块与接口契约

1. 验证 Grok Bot 可编辑前端的构建入口与运行方式。
2. 核对核心组件依赖，标明可直接迁移、需要适配、需要重建的部分。
3. 对照 Omega 当前接口列出消息、历史、事件、审批和群组契约。
4. 确认原生平台桥接和代码、资源来源。

交付：模块清单、协议映射和首批迁移边界。以实际运行结果决定迁移范围，不仅依据文件名判断能力完整。

### 阶段二：完成单会话纵向闭环

1. 在 Omega 中建立独立新版前端入口，复用侧栏、聊天区和输入框。
2. 接入真实 Omega 服务，完成认证、已有会话读取、历史分页和定位。
3. 打通发送、停止、流式更新、工具结果、审批和模型设置。
4. 接入附件、草稿、全屏编辑及断线恢复。

交付：可以连接真实服务并继续已有会话的新版客户端。现有前端在验证期间保留为回退入口。

### 阶段三：接入群组协作

1. 迁移成员和群组相关组件，绑定现有群组服务。
2. 接入连续提问、指定成员、回复追问及成员进度。
3. 接入问题定位、时长、并发设置和成员编辑。
4. 验证同一会话在单聊和群组中的状态一致性。

交付：覆盖当前 Omega 核心群聊能力的新界面，保留现有调度语义。

### 阶段四：多端整合与切换

1. 完成桌面和手机布局，处理 Android 安全区域与软键盘。
2. 用 Tauri 平台适配替换所需 Electron 接口。
3. 打包 Web、macOS、Windows、Android；每个平台分别记录构建及运行验证结果。
4. 核查现有 HTTP/FRP 连接场景的认证、长连接和重连行为。
5. 核心验收完成后切换默认入口，按实际使用反馈决定旧前端退出时间。

交付：各端可使用的新版客户端及运行说明。缺少某平台构建或运行环境时明确列出未验证项，不以资源打包成功代替安装运行验证。

## 8. 性能要求

- 进入会话才读取所需历史，不预加载所有会话正文。
- 长历史按需分页或窗口化渲染，缓存有上限并可淘汰。
- 大工具输出、图片原图和预览按需加载。
- 流式事件按帧或短时间批量更新，避免每个 token 重建整条消息列表。
- 离开会话后释放不必要订阅、观察器和资源对象。
- 用户翻阅历史时不强制跳到底部；接近底部时才自动跟随。
- 使用相同长会话样本对比迁移前后的内存、渲染耗时、输入响应和 DOM 数量。

阶段一记录可复现样本和设备基线；后续以测量结果判断收益，不假定 React 或现有组件天然更省内存。

## 9. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 已有上下文 | 打开已有会话后可继续提问，保持原会话 ID 和工作目录 |
| 长会话 | 历史按需加载，输入和发送流畅，切换多次后缓存受控 |
| 多端使用 | 一端发送，另一端可看到服务端进度和最终结果 |
| 网络中断 | 重连后补齐状态，不丢失已接收任务，不因重试重复执行 |
| 审批与停止 | 操作作用于正确轮次，多端重复操作得到明确结果 |
| 指定成员 | 明确指定成员的提问沿用直接路由，忙碌时可等待 |
| 群组调度 | 空闲且满足依赖和目录规则的任务可并行执行 |
| 图片 | 上传和粘贴可用，过期后有明确提示 |
| 输入体验 | 组合输入不误发送，全屏切换保留草稿与引用 |
| 响应式布局 | 桌面折叠释放空间，手机按钮不与系统栏和键盘重叠 |
| 原生客户端 | 各目标平台分别完成构建、连接和核心聊天验证 |

验证组合：契约测试覆盖协议转换与状态恢复，浏览器测试覆盖关键交互，人工验证实际设备与 FRP 连接。业务调度回归复用现有测试。

## 10. 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 重建组件行为不完整 | 先验证真实交互和构建，再决定迁移或重建 |
| Grok Bot 协议与 Codex 数据不同 | 在 Omega 适配层统一转换，组件使用稳定展示模型 |
| 组件依赖 Electron 或原后端 | 提取平台接口，分别实现浏览器和 Tauri 适配 |
| 新界面增加渲染与内存成本 | 用同一长历史样本做迁移前后对比，限制缓存与渲染范围 |
| UI 与现有功能不同步 | 以验收矩阵核对附件、审批、群组和模型设置等能力 |
| 文档与打包脚本不一致 | 以源码、构建结果和实际运行行为确定依赖 |
| 复用代码和资源来源不清楚 | 建立来源记录，确认适用条件后纳入工程 |

## 11. 首版不包含的工作

- 整体迁入 Grok Bot 的推理、协调和工具执行后端。
- 迁移原应用账号体系、云电脑或远程沙箱。
- 承诺所有 Grok Bot 功能自动获得 Codex 对应能力。
- 在客户端各自运行 Codex，形成多份独立工作上下文。
- 大规模改写已经可用的 Omega 群组调度和持久化逻辑。

首个实施里程碑是阶段二的真实单会话闭环：借用已有客户端组件，可靠地连接 Omega 服务端并继续现有 Codex 会话。通过这个里程碑验证复用方案，再推进群组和全平台切换。
