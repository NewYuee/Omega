# 飞书机器人连接器（第一版）

飞书是 Omega 的消息入口，不是新的模型运行环境。连接器默认关闭，使用飞书自建应用机器人及官方 Node SDK 长连接；不需要为接收消息暴露公网回调端口。

## 支持范围

- 飞书群绑定已有 Omega 群组；私聊绑定已有独立个人会话。
- 群里必须 @机器人；私聊直接发送文本。默认直接处理，`/讨论 问题`、`/交接 问题` 选择群组协作模式，沿用 Omega 默认预算。
- 最终结果、讨论最终小结、暂停异常关联原消息；普通群使用主消息流中的引用回复，不强制话题回复。只同步从飞书发起的任务，不广播 Web 中的其它历史或任务。
- 最终正文使用 Card 2.0 Markdown 卡片，保留段落、列表、链接和代码。任务完成／失败／取消后优先更新已确认送达的处理卡，并移除停止按钮；长正文以编号续页发送。更新被飞书明确拒绝时发送新结果卡，网络超时则标记结果未知，不自动重发。
- 群组成员的结构化决策变成 Card 2.0 表单：方案、补充说明、提交。选择“其他方案”时在补充说明填写方案内容。
- 接收任务后提供停止按钮。只有原提问者且仍符合该绑定的授权范围才可操作；转发卡片不能获得权限。停止不回滚已经发生的操作。
- 默认仅白名单成员可使用。在「工作控制中心 → 连接与插件 → 飞书机器人 → 会话绑定与白名单」中，将指定群的「群成员使用范围」设为「允许此群所有成员使用」，确认并保存后，该群成员无需逐个配对即可 @机器人提问。此范围包含以后新加入的成员，共享目标上下文并消耗模型额度；不开放其他群或私聊，执行审批不变。关闭后恢复保留的白名单；界面更换目标时自动恢复仅授权成员。
- Codex 工具执行审批、个人会话原生问答、预算追加和复杂管理仍在 Omega 处理，不通过机器人自动批准。
- 提问入口仍接收文本（最多 12000 字符）；可以回复／引用群内或私聊的图片、文件后发送文本问题。直接发送图片／文件、富文本 post、自动创建或群内命令修改绑定暂不支持。
- 引用链沿 `parent_id` 逐层读取，最多 20 层，每层必须属于同一聊天；不按 `root_id`、`thread_id` 拉取整个话题历史。循环引用、跨聊天、删除或无权限时整体停止派发并回告。模型按最近引用到更早原文的顺序收到每层消息 ID、作者 ID、正文及附件对应关系。
- 引用中的命令不会改变执行模式；引用中的 @成员不会触发 Omega 的直接成员调度。引用作为参考资料，不是额外执行授权。已保存的引用链与附件 ID 随任务持久化，重启不重复下载；旧版只缓存直接文本的任务保留原快照，并明确注明没有更早引用。
- 引用图片支持 PNG/JPEG/WebP，单张 8 MB、2400 万像素，复用 Omega 的图片校验与压缩，通过模型图片输入发送，不只是文件名。
- 引用文件支持 UTF-8 文本／代码（单个 500 KB）和 PDF、DOCX、XLSX、PPTX（单个 10 MB）。复用现有隔离解析器，仅提取文字和表格，扫描 PDF 不做 OCR、公式不重新计算；旧版 Office、宏、压缩包及任意二进制文件不执行、不解包。提取文字作为 Omega 文本附件交给模型。
- 每条引用链最多 20 个附件，累计下载最多 32 MB，文件提取文字累计最多 2 MB；逐个下载，流式限量读取，有下载超时及引用链总处理时限。单条引用文本最多 10000 字符，提问、引用文本及附件标记合计最多 12000 字符，不静默截断。
- 任何层级或附件读取／解析失败、资源过期、非支持类型或超限，均回告“本次提问未交给模型”，不会忽略该部分继续猜测。请修复权限、缩短资料或重新引用后提问。附件沿用 Omega 的 7 天清理周期；文件名不作为服务器写入路径，下载只使用校验后的消息 ID 与资源 key。

## 1. 创建飞书应用

在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，开启机器人能力。

启用机器人发消息权限 `im:message:send_as_bot`，接收群内 @机器人消息权限 `im:message.group_at_msg:readonly`，私聊需要 `im:message.p2p_msg:readonly`。根据后台提示确认权限审批及应用可用范围，然后发布应用版本，将机器人加入目标群。

引用及资源读取需要相应消息读取权限（如 `im:message:readonly`），以飞书后台「获取指定消息的内容」「获取消息中的资源文件」接口的当前权限要求与数据可见范围为准；仅能接收 @消息不代表能够读取被引用的其它消息。机器人必须能访问原消息所在聊天。参见[获取指定消息的内容](https://open.feishu.cn/document/server-docs/im-v1/message/get)。不要为了接入引用自动扩大群消息订阅范围；Omega 仍只处理已绑定群内符合授权范围的用户 @机器人发起的提问。

在“事件与回调”中选择长连接接收：

- 事件订阅：`im.message.receive_v1`。
- 回调订阅：`card.action.trigger`。仅配置事件订阅不会收到决策／停止按钮回调。

以后台当前权限说明为准。实现依据：[官方 SDK](https://github.com/larksuite/node-sdk)、[官方卡片回调说明](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-card-action-reply.md)。

## 2. 在 Omega 界面配置（推荐）

入口：**工作控制中心 → 连接与插件 → 飞书机器人**。

1. 填写 App ID、App Secret，点击「验证并保存连接」。Omega 向飞书校验凭据，自动读取机器人 open_id，保存后建立长连接。若后台提示没有长连接，先做这一步，再返回飞书后台保存订阅。
2. 点击「生成 5 分钟一次性配对码」，复制命令。群里 @机器人发送，私聊直接发送。配对消息只用于识别聊天和用户，不交给模型。
3. Omega 显示识别到的 chat_id、用户 open_id；选择已有 Omega 群组或独立会话，核对授权范围，点击「确认授权并绑定」。群聊绑定群组，私聊绑定独立会话；不允许绑定群组成员或协调者会话。
4. 后续可修改目标、移除白名单用户或整个绑定，也可设置「打开 Omega」地址。目标、白名单和地址修改需要点击「保存绑定设置」；未保存时会显示提示，可选择「放弃修改」。移除整个绑定则在确认后立即保存，失败会保留原项并显示原因。存在其他未保存修改时，先保存或放弃再移除。增加白名单用户时，生成新的配对码让该用户发送，再确认同一目标；相同目标会合并白名单，更换目标则重置为本次配对用户。
5. 多个飞书群可绑定同一个 Omega 群组，无需先移除旧绑定。配对列表会标注已绑定的聊天数量；这些聊天共享目标上下文，若需要隔离，请创建不同的 Omega 群组。
6. 保存、重连、停用均不需要重启 Omega。有执行中任务或待回传消息时拒绝修改，请先结束对应任务并等待回传。配置采用版本校验，多窗口修改冲突时需刷新后重试。

未绑定时仅允许配对，不执行任务。配对码短期有效、一次性使用，重生成会作废旧码；持有码不等于获得会话权限，必须回到已认证的 Omega 界面确认。识别结果显示应用作用域 ID，不额外申请通讯录权限获取姓名。

凭据使用 AES-256-GCM 加密后写入 `.omega/feishu-secret.json`，本机密钥在 `.omega/feishu-secret.key`，文件权限为 `0600`；两者均不进入 Git 或普通备份。加密防止只泄露配置文件时直接读出凭据，不能防护同时拿到本机密钥的系统用户。跨机器迁移应重新填写凭据，或单独安全迁移这两个文件。Secret 不回显、不写日志；远程配置使用 HTTPS 或 SSH 隧道，不通过公网明文 HTTP 输入密钥。

已有 `OMEGA_FEISHU_APP_ID` / `OMEGA_FEISHU_APP_SECRET` 环境变量时，界面显示「由部署环境管理」，不允许覆盖或混用本地凭据。更换应用必须确认清空旧绑定。连接校验验证凭据和机器人身份，不代替飞书后台权限、事件订阅和发布检查。

## 手动配置服务端（兼容已有部署）

通过部署环境或私有服务配置注入以下环境变量，不提交到 Git：

```text
OMEGA_FEISHU_APP_ID=cli_你的应用ID
OMEGA_FEISHU_APP_SECRET=你的应用Secret
```

在 `OMEGA_STATE_DIR` 下创建 `feishu.json`（默认 `omega/.omega/feishu.json`）。下方值均为占位符，需换成真实 ID：

```json
{
  "enabled": true,
  "botOpenId": "ou_机器人open_id",
  "omegaUrl": "https://你的Omega地址/",
  "bindings": [
    {
      "chatId": "oc_飞书群ID",
      "chatType": "group",
      "userIds": ["ou_你的用户open_id"],
      "target": {"kind": "group", "id": "Omega群组ID"}
    },
    {
      "chatId": "oc_与机器人私聊的会话ID",
      "chatType": "p2p",
      "userIds": ["ou_你的用户open_id"],
      "target": {"kind": "thread", "id": "已有Codex个人会话ID"}
    }
  ]
}
```

只保留需要的绑定。每个飞书 chat_id 只能绑定一个目标，每个绑定必须显式列出用户 open_id，不能写 `*`。open_id 属于应用作用域，不能拿其它应用下的 ID 直接替代。机器人身份可以从飞书获取机器人信息接口取得，消息事件可用于确认 chat_id 与发送者 open_id；请勿在公开日志中打印整个事件或凭据。

Omega 群组 ID 可从已认证的 `/api/groups` 获取；个人会话 ID 使用会话的 thread ID。个人目标不允许绑定群组成员／协调者会话，以免绕过群组调度。

`omegaUrl` 可省略；若填写，必须是不带用户名、密码、查询参数或访问密钥的 HTTP(S) 地址。它只是“打开 Omega”入口，不自动登录，也不保证飞书设备能访问你的内网地址。

重启时，确保 Omega 服务进程能读取环境变量。LaunchAgent/systemd 不一定继承 SSH 终端的环境；仅在 SSH 终端 `export` 不会改变已启动的守护服务。手工修改文件后需要重新连接；更改部署环境变量需要重启守护进程。界面保存的配置即时生效，无需重启整个服务。

## 3. 验证

在 Omega 的“工作控制中心 → 连接与插件 → 飞书机器人”检查长连接状态。已认证的 `GET /api/feishu` 提供连接状态及队列计数，不返回密钥或消息正文。

1. 群里 @机器人发送简单文本，确认 Omega 新增问题、飞书收到停止卡片。
2. 任务结束后确认原处理卡变成结果卡、停止按钮消失；长回复检查编号续页和代码块。普通群中应能直接阅读正文；Web 中发起的其它任务不应被发送。
3. 让成员提出结构化决策，验证选择、补充说明与提交；其它用户或转发卡片不得操作。
4. 发送测试任务并点停止，核对 Omega 中对应任务取消，不影响其它任务。
5. 默认模式下使用不在白名单的账号提问，确认不会派发；仅开放指定群后验证该账号 @提问可用，其他群、私聊、不带 @的群消息仍不能派发，其他人不能替原提问者停止或决策。

本地自动化测试使用模拟飞书事件和发送端，不需要真实凭据；真实飞书应用的权限、卡片呈现和长连接接收仍需要按上述步骤联调。

## 安全、恢复与限制

- 授权用户可以驱动已绑定的 Omega 会话，享有该会话已有工具权限；白名单不是文件系统沙箱，只应加入可信用户。开放全群时也包含未来加入的成员，仅适合可信群。群结果对群成员可见，不能把敏感个人会话随意绑定到多人群。
- 输入持久化后才确认事件，消息 ID 去重。首次接收超过 10 分钟的消息忽略；已进入本地队列的消息可在服务恢复后继续处理。最多保留 100 个待派发／执行任务，超限消息不派发。
- 派发前写入状态；服务异常时未知派发不会自动重发。个人会话能查到原 turn ID 时接回原执行；群组派发处于写入间隙的未知状态须在 Omega 核对，不能盲目再次提问。
- 回传使用稳定 UUID，并先记录发送状态。接口超时或进程退出后的发送结果标为 `unknown`，不自动重试，以免超出平台去重时间窗重复刷屏。当前没有自动补发按钮，需先核对飞书原消息，再在 Omega 获取缺失结果。
- 卡片权限按服务端持久化映射及实时任务状态校验；决策已经处理、原任务终止或绑定变化时拒绝旧卡片。卡片显示本身可能仍保留按钮，再点会提示已处理或失效。
- 超长最终结果分段回传，最多 80000 字符；超限明确提示在 Omega 查看完整内容。
- 队列及回传正文存于 `omega.sqlite`，随 Omega 数据备份；凭据与 `feishu.json` 不进入标准备份。恢复旧备份前先停用连接器并核对队列，防止旧待发内容再次发送。需要数据清理时先备份，不手动改写执行中队列。
- 新备份包含图片与 `pasted-text` 文本附件目录。恢复不会延长原有 7 天有效期；旧备份若未包含文本附件，不能恢复当时缺失的文件正文。
- 同一应用仅运行一个 Omega 连接器实例。长连接是竞争消费，不要同时启动同应用的 lark-cli 事件监听器或另一台 Omega。
- 停用方法：点击界面「停用」，或配置 `enabled:false` 并重启；未启动／配置失败不影响 Omega Web、个人会话和群组服务。
